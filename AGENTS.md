# Skolregistret — working in this repo

## Before you commit

```bash
bun run check      # typecheck + lint + test
bun run format     # prettier
```

`bun run build` is the strongest check, but it needs data — see the README.

## Language

The domain is Swedish and identifiers follow it: `Enkätfråga`,
`getBeräknatRiksGenomsnitt`, `huvudmän`, `skolenhetskod`. **Do not anglicise
them.** The API's own field names are mirrored exactly in
`src/lib/skolregister/types.ts` so that a value can be traced from the API
response to the screen without a translation step. Comments and commit
messages are in English; domain nouns stay Swedish.

`.editorconfig` pins UTF-8 for this reason.

## Layout rules

| Directory                | Rule                                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `src/lib/`               | Must stay server-safe and free of React. `skolregister/client.ts` reads the filesystem.                     |
| `src/hooks/`             | Anything `"use client"`. The one hook lives here, not in `lib/`.                                            |
| `src/config/`            | Tunables — scope, läsår, pagination, and the skolform registry. Change behaviour here before changing code. |
| `src/components/tables/` | Column definitions. Route files should not declare columns.                                                 |
| `src/lib/skolregister/`  | Import from the barrel (`@/lib/skolregister`), not the individual modules.                                  |

`src/config/skolformer.ts` is the registry that makes the app work for more
than grundskolan — filter chips, columns, stat tiles, sort options and the
detail comparison are all generated from it. Adding a skolform means adding an
entry there, not writing new components.

## Deliberately left as-is

- **`src/components/filters/controls.tsx` (373 lines, 11 exports)** and
  **`src/lib/query.ts` (336)** are large but cohesive. Not worth splitting
  unless you are already changing them.
- **`src/lib/skolregister/client.ts` and `resources.ts` have no tests.** They
  are I/O; testing them means mocking fetch or shipping a fixture export file.
  The pure logic around them is covered instead.
- **`AppShell` accepts a `crumbs` prop it never renders**, and all five call
  sites build one. See the TODO in `src/components/layout/AppShell.tsx`.

## Testing

`bun test`. Tests sit next to the code as `*.test.ts`. Fixtures are plain
literals in the test file — there is no factory layer and no network access.
Prefer pinning a surprising behaviour with a named test over silently
"fixing" it; there are two such tests already (see the README's Known quirks).
